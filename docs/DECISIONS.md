# Engineering decisions (one line each, with the reason)

Decisions the owner must take are in the last section; everything else was decided by engineering and can be revisited.

## Platform
- **Django 5.2 LTS + DRF, SQLite in WAL mode, Python 3.10-3.13** - runs on the dev PC (3.10/3.13) and on a GPU PC with 3.12; LTS gets security fixes; SQLite needs nothing installed (Postgres optional later).
- **waitress + whitenoise instead of `runserver`** - a pure-Python, threaded server that behaves on Windows; whitenoise serves the committed UI and fonts.
- **Server binds to 127.0.0.1 and only accepts localhost host names** - single-user local app; protects the local API from DNS-rebinding pages. Opening it to the LAN needs an explicit env change.
- **No Redis/Celery: durable DB-backed queue** (`jobs` app) - claim = compare-and-set UPDATE (SQLite has no row locks), lease + heartbeat, exponential backoff, timeouts, cooperative cancel (subprocesses are killed), idempotency keys, progress, logs, time/GPU accounting. An expired lease re-queues the job, so a crashed worker loses nothing.
- **Worker lanes: one GPU lane + N CPU/network lanes** - GPU jobs are serialised, ffmpeg/Piper/API calls run in parallel.
- **GPU arbiter** - one heavy job at a time; switching occupant unloads the others (Ollama `keep_alive: 0`, ComfyUI `/free`); another program's VRAM (> max(2.5 GB, 25 %) after our unload) makes the job wait and shows "GPU busy"; we never kill foreign processes. No GPU/`nvidia-smi` = no waiting.
- **Secrets only in `.env`** (git-ignored); the API never returns a key (only "set" + last 4 characters); logs redact bearer tokens and keys.
- **Built UI is committed** (`instai/static/app`) - the GPU PC needs only Python. `START.bat` rebuilds only when Node exists and the **source hash** (not timestamps, which git rewrites) changed.
- **Own tiny JSON-schema validator/repairer** instead of the `jsonschema` package - zero extra dependencies, and "repair" (coerce types, drop unknown fields, clamp) is needed anyway.

## Generation
- **Every LLM call goes through one function** (`agents/runner.py`): structured output natively when the backend supports it (Ollama `format`, OpenAI `json_schema`/`json_object`), then extract -> repair -> validate -> semantic checks -> send the problem list back and retry (3 attempts). A gateway that rejects `response_format` is retried without it (not counted as a failure).
- **Storyboard falls back to a deterministic script->shots builder** when the model cannot cover the script after retries - a weak model never stalls the pipeline; the fallback is logged and flagged.
- **Agents are roles, not models; they never write to the database** - results are persisted only by `story/services.py`.
- **Proposals (strategy, series plan) are not saved until the owner edits/accepts them** - the owner stays in control; the wizard shows editable fields.
- **Continuity = typed StoryMemory entries, never chat history** - the digest (latest state per subject, still-open threads, last summaries) is injected into prompts; re-running an episode replaces only that episode's entries; threads are resolved by matching text.
- **Continuity is updated when the script is approved**, not when generated - unreviewed text does not pollute the memory.
- **Storyboard is reviewed in the `storyboarding` state; pressing "produce" approves it** - fewer clicks for a non-technical owner; the state history records it.
- **Explainers: only system-fetched or owner-added text becomes a Source** (`verified` = fetched by the system); a claim without a source cannot be "established"; numbers in the script that appear in no claim/source are flagged. Source retrieval is off by default (owner adds sources) with Wikipedia as an optional fetcher.
- **Anime What-If defaults to original characters**; fan content is an explicit per-series switch and always shows the "no commercial rights" notice. Real-looking presenters: synthetic or consented only (notice).
- **Never auto-publish.** `automation_level` is stored but changes nothing until Phase 4; publishing in release 1 is a manual-export zip (video, cover, caption, hashtags, reminder) behind an adapter interface.

## Production
- **Hash-based staleness**: every asset stores the hash of the inputs that produced it. Editing one shot makes only its keyframe/narration/clip stale; approved assets are reused; editing clears the approval of the assets it makes stale; a failed video job never touches script/storyboard (tested).
- **`advance()` is re-entrant and runs after a job is marked done** - two steps finishing together cannot both see the other as "still running".
- **Preview vs final**: preview = 360x640 @15 fps, ultrafast x264, small keyframes (448x800); final = 1080x1920 @30 fps. Estimated GPU time is shown for both before anything runs, labelled "estimate" until the benchmark replaces it.
- **Camera**: Ken Burns via `zoompan` over a 1.5x/2x oversampled still (no jitter); parallax needs RGBA cut-out layers (BiRefNet, Phase 3) so until then it falls back to Ken Burns and says so in the QC notes. Techniques without a renderer yet (puppet_2d, motion_graphics, talking_video, three_d) fall back the same way.
- **Two-stage assembly**: silent per-shot clips are cached as assets, then one pass joins (xfade/concat with normalised timebase), places each narration at its shot start, mixes, loudness-normalises (-16 LUFS) and burns subtitles. Narration length drives shot length - speech is never cut.
- **Persian subtitles = ASS burned by libass** (HarfBuzz + FriBidi shaping) with the **Vazirmatn font bundled** (SIL OFL, licence text included) so output is identical on every PC; an RTL mark prevents numbers/Latin at a line start from flipping the paragraph. Verified visually on a rendered frame.
- **ComfyUI graphs are versioned JSON templates** adapted from the owner's NMarketing graphs (`flux_dev_fp8_t2i@1`, `wan22_i2v_a14b_fp8@1`); each declares input schema, nodes, model files, VRAM, licence and expected time; availability is checked against `/object_info` including the model file names. Wan at 480x832 portrait (9:16), <= 81 frames @16 fps, 8-step lightx2v.
- **Image engine `auto` never silently uses placeholders**: no ComfyUI = a clear Persian error. Placeholders/fake voices/fake LLM only through the explicit **demo mode** switch.
- **TTS**: Piper through its CLI, MOSS through the existing server protocol (`/health`, `/run`); `auto` prefers MOSS, then Piper, never the fake engine. Pocket-TTS and Edge TTS are excluded (licence).
- **QC**: technical (codec, resolution, audio, duration, loudness within 3 LU, black/frozen frames), script (completeness, length, reading speed), continuity (speakers known), explainer claims. Warnings do not block; failures keep the episode in quality review.

## Setup and delivery
- **`START.bat` is the only entry point**: finds Python 3.12/3.13/3.11/3.10, else installs 3.12.10 per-user (pinned size + sha256, no admin), creates `.venv`, installs pinned requirements (PyPI, then mirrors), fetches ffmpeg, builds the UI if possible, migrates, prints an English checklist, starts server + worker (each restarts itself), opens the browser. Folder names with spaces/parentheses are supported (relative paths only).
- **ffmpeg comes from PyPI first** (the `imageio-ffmpeg` 0.6.0 wheel contains the same Gyan 7.1 essentials build with libass/x264/zoompan/xfade; PyPI gives the sha256) with the GitHub zip as fallback. Measured from the dev PC in Iran: GitHub release assets 15-70 KB/s with timeouts, PyPI ~450 KB/s. The wheel has no ffprobe, so probing falls back to parsing `ffmpeg -i`.
- **Downloader is stdlib-only** (runs before the venv exists): manifest driven, resumable (Range), size + sha256 verified (a missing hash is recorded on first use and checked afterwards), HF mirror fallback, reuses files ComfyUI already has, never deletes (bad files are renamed), refuses to start without free space + 2 GB. Default set is small (ffmpeg + Piper); Wan/FLUX/MOSS/ACE-Step are optional packs.
- **Hash/URL data for big models was copied from the owner's Qasem manifests** (pinned commits); Piper/Rhubarb/FLUX only have sizes (no hash) and are marked unverified.
- **Tests never touch the real data folder**: pytest gets a temp data dir and a file-based test database; real adapters are tested against in-process fake Ollama/OpenAI/ComfyUI/MOSS servers.
- **UTC in the database, Jalali dates in the UI** (`Intl` with the Persian calendar) - no date library.
- **UI**: React + TS + Vite with only react, react-dom, react-router-dom; own components, logical CSS properties for RTL, Persian first with an English dictionary, light/dark, Vazirmatn bundled, no CDN.

## Studio workflow (development room, pre-production, look library, bilingual UI)
- **The pipeline mirrors real animation studios, researched from sources** (`docs/STUDIO_PIPELINE.md`): development (pitch, series bible, series composition, greenlight), pre-production (script, storyboard, animatic, design sheets and colour script, casting), production hand-off, retakes. Each stage = one InstAI stage + one AI role + one human gate. AI is the crew, the owner is the director; every role is one validated model call and none can write to the database.
- **Formats became templates (data, not code)**: the three launch formats plus "custom" ship as built-in templates; the owner duplicates / edits / writes new ones in the Library (step kinds: source, research, brainstorm, profile, map, timeline, factcheck; bible + composition + final gate always close the template). `base_format` keeps the policy notices (fan content, sourced, presenter). Why: the platform must not be limited to three formats.
- **Brainstorm boards are rows, not chat**: every idea card (AI or human) can be edited, rated, merged (by hand or by the model), refined (a child card is made, the original stays), rejected, approved, and "more like this"; rejected titles are not proposed again. Approved ideas feed the next steps.
- **Canon research uses only text the system fetched (or the owner pasted)**; every character / arc / event / rule cites stored Source ids; the model is told not to add anything from memory. Fetched text is internal notes (a licence consequence, see below), scripts are written from our own bible.
- **Real-series lookup: AniList + Wikipedia on by default, Fandom opt-in, Jikan OFF** - AniList allows low-volume on-demand use but forbids hoarding and needs a commercial licence above about $150 revenue per month; Wikipedia / Fandom are CC BY-SA; Jikan scrapes MyAnimeList whose terms are personal / non-commercial. One title at a time, only on request, failures reported per provider, manual entry always works (the owner is in Iran). **Owner decision pending: the AniList commercial licence once revenue passes the threshold.**
- **A real source series makes the series fan content automatically** (notice shown); original characters stay the default for everything else.
- **Gates follow the automation level** (manual: all; assisted: bible, composition, storyboard, final gates; automatic: only the final gates); an auto-passed step is marked "auto" and re-opens if edited; nothing is ever published automatically.
- **Pre-production is a layer over the existing state machine, not a new state**: stage status is derived from real content (script, shots, animatic asset + input hash, design sheets, character voices); only the human approvals are stored (`Episode.studio`). With `production.studio_mode` on, `storyboarding -> asset_generation` is refused until the gate is approved; default OFF so the first release's flow and its tests are unchanged, the wizard turns it ON for new pages.
- **Animatic = existing render path at preview size**: timed stills (approved keyframe, else a labelled placeholder card) + scratch narration from the page's TTS engine (silent and reading-speed timed if none is ready) + burned subtitles; its asset stores a hash of the shots, so a changed shot makes it stale and clears its approval. It never changes the episode state and needs no GPU.
- **Retake request = a director's note + regenerating ONE shot** (`studio.RetakeRequest`, `story.services.regenerate_shot` shared with the old endpoint; narration-only retakes now clear only the narration). An open request counts as done when a newer asset of that kind exists. It is separate from `production.Retake` (re-render a TIME RANGE of a finished video with seamless stitching): a request is the note, a range retake is the heavy fix.
- **Style library**: built-in presets (44 styles across 8 realism levels, 10 animation approaches; 16 themes with palette, light, mood and typography) live in code, user presets in the database; duplicate / edit / delete / export / import (JSON bundle `instai.styles@1`). **No studio, franchise, artist or character names in any prompt** (a test scans for them): styles are described by visual traits so output cannot be mistaken for a rights-holder's work. `formats.STYLES` is a live list (built-ins + user presets) so production code that looks a style up by `style_key` keeps working; legacy keys (`anime_soft` ...) alias to the new presets.
- **Text model per page and per task group** (`production.llm`: default, per-group, fallback; only provider and model NAMES are stored, keys stay in `.env`): resolved by `agents/llm.py`, used by every story / studio job, with a `FallbackProvider` that tries the next provider on a provider error. Job resource (cpu / gpu / net) comes from the page's choice, so a brainstorm via API does not wait for the GPU. Translation prefers an installed `translategemma` model when none is chosen.
- **Bilingual UI**: fa (RTL) and en (LTR), switchable, remembered in the browser AND on the server (`ui_language`); the API sends `X-Lang` and answers errors in English (generic text per error code, specific text where the code supplies it); texts live in `src/i18n/fa.ts`, `en.ts` and `packs/*.ts` (workstreams add a pack file, no edits to shared code) and `tests/test_i18n.py` fails if a key is missing in either language, used but undefined, or if an English text holds Persian. Job titles are translated by job kind in the UI.
- **Translation of an episode** stores `Episode.translations[lang] = {script, shots: {shot_id: text}}` (script blocks and per-shot narration, same count and order) and leaves the original untouched; rendering a bilingual video from it belongs to production.
- **Voice casting reuses the production voice stack** (`production.VoiceCast` per character and language, engines with licence badges): the Studio tab lists the voices of every engine that is ready, flags non-commercial engines (the AI casting never picks them) and writes a `VoiceCast`, which production resolves first. No second casting system.

## Phase 3 / 4 (animation, voices, two GPU PCs, automation)
- **Voices: every engine the owner has, with a licence badge.** MOSS-TTS+Persian LoRA (speech + consented cloning), Piper, Pocket-TTS (CC-BY-NC), Edge TTS (unofficial online), MOSS-SFX, ACE-Step. Pocket and Edge were excluded before; the owner asked for them, so they are available but NEVER chosen by `auto`, show a visible warning wherever a voice is picked and a `voice_licence` warning in the QC report. The audio servers use NMarketing's protocol (`/health`, `/run`; ACE-Step REST) and run on demand from `venvs/`; the arbiter stops them when ComfyUI/LLM needs the card; `INSTAI_VOICE_FAKE=1` runs the same scripts with test tones.
- **Voice casting = `VoiceCast(character, language)`**, resolved before the older `Character.voice` JSON (which also honours `voices_by_language` of the pre-production step). A cloned voice is used only if its recording has consent text stored with it.
- **Puppet 2D = Pillow + one ffmpeg pipe** (no new dependency): rig JSON (parts, pivots, parents, z), keyframed motion library with easing, additive motion layers, deterministic blink, parallax layers, camera. Render speed measured on the dev PC (i5-4590): ~23 fps at 360x640. Rig sources: demo drawing, PNG-layer ZIP, PSD (optional psd-tools), or a draft from the character sheet (FLUX/Qwen part images + cut-out; the owner fixes pivots in the rig editor).
- **Lip-sync = Rhubarb (MIT) + loudness.** Measured on real audio: Rhubarb works for English (pocketSphinx) and for Persian (`phonetic` recogniser); the phonetic recogniser labels pauses as speech, so cues are closed (X) over real pauses found from loudness. Fallback without Rhubarb: amplitude-driven mouth.
- **Two PCs: pull model over HTTP, token auth, one-time pairing code.** PC A shows an address + code; PC B (START-WORKER.bat) enters them once and gets a token (only its SHA-256 is stored). Security choice: the normal server stays on 127.0.0.1; enabling workers starts a SECOND listener (0.0.0.0:8766, off by default) behind `WorkerGate` that answers 404 to everything except `/api/worker/*` (token or pairing code required, failed attempts throttled). The UI, media, settings and the management API are never reachable from the LAN. Windows may ask once to allow the firewall.
- **Routing: capability + VRAM + busy + measured speed; one heavy task per GPU; VRAM never pools.** Tasks are pure compute with files in/out (`comfy.graph`, `voice.tts|sfx|music`, `bench.node`), claimed atomically with a lease; a vanished worker's task fails (retryable) and the job falls back to another device. Device choice is reserved atomically so two shots never take the same idle GPU. Verified with two real OS processes.
- **Hero shots.** Keyframe from the approved sheet (Qwen-Image-Edit if a PC has it, else FLUX img2img, else prompt only); Wan I2V / first-last-frame; >5 s chained through the last frame; colour-matched to the keyframe (mean/std, smooth in time); consistency QC with a built-in colour+structure embedding (weak: catches big drift; thresholds are heuristics until calibrated on real clips; a stronger embedder can be plugged in).
- **Retake** = ffmpeg + Pillow: boundary frames -> first/last-frame Wan -> colour match -> fit to exact frames -> seam blend -> ONE re-encode; audio keep/mute/replace/cut; verified for exact duration/frame count/A-V sync. A retake edits the rendered video; a full re-render starts from the shots again (revert is one click).
- **Mix:** music / ambience / SFX tracks are generated (a worker PC can do it), placed on the timeline and ducked under dialogue with a side-chain compressor (measured: the bed drops by more than 6 dB under speech).
- **Anime comparison:** same stills + same seeds + same sampler/LoRA for Wan 2.2, AniSora V3.2 GGUF and AnimeGen GGUF; a candidate no PC can run is `skipped`, never faked; the owner's vote sets the page default used by hero shots. All three new graphs and the Qwen/LoRA-training graphs are UNVERIFIED on a real ComfyUI (marked in the workflow table).
- **LoRA training** (`TrainLoraNode`) is optional and measured: same prompts/seeds before and after, scored against the references; a 12B model may not fit 12 GB - the job then says so plainly.
- **Automation levels** (manual / assisted / automatic) drive the pipeline from a tick in the worker: assisted runs previews and asks before costly steps; automatic also approves the script, makes the final render inside the weekly GPU-minute budget and the render windows ("nights only"), and schedules the next publication slot. The owner always approves the finished episode. Budgets count job GPU seconds (including worker time) and LLM tokens x the prices set in Settings.
- **Never auto-publish.** Default = manual export package + reminder when the slot arrives. The Instagram Graph adapter is a skeleton behind `INSTAI_FEATURE_INSTAGRAM_API=1`; it needs a Professional account, a Facebook Page, a token in `.env` (never the database/API), a public https media URL and an API target switched on by the owner; automatic posting additionally needs a per-page enablement typed with an exact confirmation sentence. Nothing bypasses authentication or rate limits.
- **UI area = "Production lab" (`/lab`)** in its own files and i18n namespace (`labFa`/`labEn`); the app shell, i18n core and other screens belong to the other agent.

## Model discovery and optional downloads (2026-10-29)
- **InstAI finds installed models itself** (`core/discovery.py`, stdlib only, cached in `data/discovery.json`): the owner said the models were on the PC but InstAI did not see them (it only looked in its own folder and at a running ComfyUI with exact file names). Searched: manual folders, env hints (COMFYUI_DIR, NM_HOME, NM_DATA_DIR ...), `%USERPROFILE%\NMarketing-data`, the Desktop 4 levels deep, Downloads/Documents, the user folder, the folders around InstAI, then FIXED drives 3 levels deep; groups in that order so a big drive cannot eat the time budget (12 s / 60,000 folders) before the Desktop is done. Network and removable drives are never scanned; links/junctions are not followed.
- **Markers, not paths**: a ComfyUI is a folder with main.py + comfy/ + custom_nodes/ (launcher = run_nvidia_gpu.bat beside it, Python = python_embeded); NMarketing's voice parts are found one by one (`models/moss-tts|moss-sfx|acestep`, `venvs/<engine>`, `vendor/MOSS-TTS|ACE-Step-1.5`, Piper under `tools/PersianAiKit/...`) because NMarketing is moving its heavy data to another folder; a complete copy beats an incomplete one, then the newest marker file wins; a venv whose base Python is gone is reported, not used.
- **ComfyUI models are matched by file name**, any sub-folder, any letter case, plus aliases (`FLUX.1 [dev] FP8.safetensors` = `flux1-dev-fp8.safetensors`), in every folder ComfyUI reads (models/, extra_model_paths.yaml, ComfyUI Desktop's extra_models_config.yaml) and in the running ComfyUI's /object_info. The graph is rewritten to the name THIS ComfyUI lists right before it is queued (`ComfyClient.queue_prompt` -> `workflows.adapt_graph`), so a worker PC with another layout works too.
- **InstAI starts ComfyUI when a task needs it** (`providers/comfy/launcher.py`): the python + main.py line of run_nvidia_gpu.bat plus `--disable-auto-launch` (no browser tab), output in `data/logs/comfyui.log`; routing counts the workflows whose files are on disk when ComfyUI is stopped but startable. It never stops a ComfyUI it did not start.
- **Voice engines run from where they are found**: the servers got `--models-dir/--vendor-dir/--work-dir`; NMarketing's files are only read, scratch files go to InstAI's data folder.
- **Optional downloads ask first**: candidates live in `manifests/*.json` (`offer` block: why fa/en, licence + link, commercial flag, needs); the Models page shows name, size still to download, licence and why, and the API refuses without `confirm: true`. Pinned commits + sha256 for all of them (read 2026-10-29). Candidates: Index-AniSora V3.2 GGUF (18.1 GB), AnimeGen I2V GGUF (19.3 GB), both with the ComfyUI-GGUF node (pinned zip + the gguf wheel installed into ComfyUI's own Python with --no-deps), and Animagine XL 4.0 Opt (6.9 GB, SDXL anime stills, CreativeML Open RAIL++-M, new core-nodes workflow `sdxl_anime_t2i`). Nothing measured yet.
- **Downloader**: reuse = same name (or alias) and size anywhere the selected ComfyUI sees, or listed by the running ComfyUI, or a voice file in a discovered NMarketing folder; free space is checked per destination drive.
